# 代码库阅读报告模板

## 1. 项目全貌

- 项目解决的问题
- 主要使用者
- 技术栈与运行时
- 构建、启动和测试命令
- 主要入口文件

## 2. 一张系统图

画出外部输入、入口、核心模块、存储、外部服务和最终输出。箭头表示真实调用或数据流，并附源代码位置。

## 3. 目录与模块地图

| 模块 | 作用 | 入口 | 输入 | 输出 | 主要依赖 | 证据 |
|---|---|---|---|---|---|---|

只把具有独立职责的目录或文件组视为模块。不要把每个文件机械地列成一个模块。

## 4. 核心执行路径

每条路径按实际调用顺序解释：

```text
触发条件
  → 入口函数
  → 输入校验
  → 核心处理
  → 状态或外部调用
  → 输出
```

至少覆盖：启动流程、一条主要业务流程、一条错误路径。

## 5. 模块详解

每个模块使用同一结构：

```markdown
### 模块名

**一句话作用**

**入口与调用方**

**输入**

**输出**

**实现步骤**
1. ...
2. ...
3. ...

**依赖与副作用**

**错误处理**

**测试覆盖**

**代码证据**
- `path/to/file.ts:42`
```

## 6. 数据与状态

- 核心数据结构和生命周期
- 数据库表、文件或缓存
- 哪些模块拥有写权限
- 事务、一致性和并发处理

## 7. 配置与边界

- 配置文件与环境变量名
- 外部服务和协议
- 权限与信任边界
- 不得展示配置值、密钥或用户数据

## 8. 构建、测试与部署

- 本地开发流程
- 构建产物
- 测试层级与覆盖空白
- 部署入口和运行环境

## 9. 设计判断

- 当前实现为什么这样分层
- 明确的权衡
- 容易误解的地方
- 只列有证据的风险和技术债

## 10. 理解测试

生成 6–10 道题，覆盖模块职责、输入输出、调用链、副作用和失败路径。报告中不保存答案。
