# CS329A 分课报告写作规范

## 目标

读者不需要先懂论文术语，也能回答三个问题：发生了什么、为什么这样做、什么时候不成立。术语用于精确表达和检索，不能代替解释。

## 固定工作流

1. 建立证据表。每条内容记录视频时间、投影片页码、逐字稿原句、论文页码、教师补充和字幕纠错。
2. 按课堂推进顺序划分 3–6 个知识块。每块只回答一个口语化问题。
3. 先写不含术语的解释稿，再补回必要术语。
4. 逐页说明：这一页讲什么、为什么现在讲、怎样理解、与前后页有什么关系。
5. 分别检查通俗语言、事实边界和结构完整性。

## 固定页面结构

1. 版本与材料：视频发布日期、授课日期、官网版本、官方 PPT 状态和替代材料。
2. 知识地图：每块给主题、页码、时间段和一个核心问题；附一条推进链。
3. 每个知识块包含：
   - 问句式标题。
   - 2–4 句白话导语，不出现未解释缩写。
   - 按页码排列的讲解。
   - 必要公式、数字例子和投影片。
   - 至少一个边界条件或工程限制。
   - 自然引出下一块，但不提前讲下一块内容。
4. 字幕纠错、测试题、完整逐字稿和来源放在末尾。

## 语言硬规则

- 先讲动作和目的，再给专业名称。首次出现采用“白话解释 → 中文术语 → 英文或缩写”。
- 每段只承担一个判断。每段 2–5 句，不超过 260 个汉字；单句不超过 90 个汉字。
- 每个抽象判断至少配一个动作、数字例子或可想象场景。
- 一个句子最多引入一个新术语，同一段最多引入两个新术语。
- 英文只用于论文名、模型名、公式变量和术语首次定义。
- 过渡句必须说明前一部分解决了什么、现在还缺什么。

不使用这些空泛表达：赋能、抓手、范式升级、形成闭环、打通链路、能力跃迁、端到端提效、实现质的飞跃、显然、众所周知、容易看出。

这些词必须先用白话解释：鲁棒、泛化、对齐、涌现、搜索宽度、搜索深度、oracle、coverage、selector、fuser、verifier、beam search、scaling law。

## 公式五步解释

每个公式依次说明：

1. 这条公式用来算什么。
2. 每个符号代表什么。
3. 一组可手算的数字例子。纯定义式可以改用具体动作例子。
4. 公式成立的前提。
5. 公式失效的条件，或它不能推出的结论。

禁止只做符号翻译，也禁止用另一串术语解释公式。

## 证据和限制

- 百分比、倍数、平均提升和 SOTA 必须同时说明模型或系统、任务或数据集、实验版本或时间、预算或比较基线。
- 论文结果写成“在 X 模型、Y 数据集、Z 设置中……”，不得写成普遍规律。
- 录像数字与当前论文版本不同时，两者都保留并标明口径。
- 区分教师讲解、论文结果、报告推导和解释性比喻。
- oracle 和理论上限必须说明真实系统能否调用。
- 每个知识块至少有一个边界条件、判断成本或工程限制。
- 图注包含页码、视频时间、图能证明什么，以及必要的限制。

## 测试题

- 共 6–10 题，以选择题和判断题为主。
- 每个知识块至少一题；至少两题考边界，至少一题考公式直觉，一题考实验数字不能外推。
- 题干使用日常语言，不以缩写记忆为考点。
- 错误选项来自课程中的真实误区，不用荒谬选项凑数。
- HTML 和 JavaScript 中不得包含答案键、评分逻辑或默认选中项。

## 人工验收

随机抽五段，让没有读过论文的人回答：发生了什么、为什么、什么时候不成立。任何一问答不出就重写。

随机抽三个术语，删掉括号中的英文后仍应读得懂。随机抽三个实验数字，在同屏必须能找到模型、任务、比较对象和适用范围。
